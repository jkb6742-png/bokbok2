# pc-a8 인수인계 (2026-11-02)

개발은 사무실 밖 PC에서, 테스트(테더링 포함)는 pc-a8에서 한다. 코드는 이 저장소(main)로 주고받는다.

## 1. 설치 (pc-a8)
```
git clone https://github.com/jkb6742-png/bokbok2.git _도구
cd _도구
npm install
npm run chrome        # 설치된 Chrome이 없을 때만 (puppeteer 캐시에 149 설치)
npm start             # http://127.0.0.1:3600
```
- 첫 가입자가 관리자가 된다. 그다음 가입자는 "관리자 승인 뒤" 방식(사용자 관리에서 승인·권한 부여).
- 앱 데이터는 `%LOCALAPPDATA%\bokbok\`(계정·설정·수집 데이터·비밀값), 전용 크롬 프로필은 `%LOCALAPPDATA%\bokbok\profiles\<블로그아이디>`.
- 테스트: `npm test` (224개).

## 2. 하얀드림치과(whitedream55) 설정 옮기기
계정 데이터는 저장소에 넣지 않는다. 개발 PC에서 아래 파일을 NAS(192.168.35.4 공유폴더) 또는 USB로 넘겨 받는다.
- 개발 PC `%LOCALAPPDATA%\bokbok\accounts.json` 의 whitedream55 항목 → pc-a8의 같은 파일 배열에 넣는다(앱 종료 상태에서). 프로필·원고 프롬프트(3,604자)·카테고리·지역 키워드·교정 금지 규칙·인용구 세로선/구분선2·히든 자리·기본 템플릿 3개가 들어 있다.
- 개발 PC `<애드포스트 프로젝트>\원고함\_사진함\whitedream55\_hidden\hidden_*.jpg` 2장 → pc-a8 같은 경로(맨처음=원장 소개, 맨마지막=위치·진료시간). 없으면 앱에서 비공개 글 https://blog.naver.com/whitedream55/224459305071 로 [이미지 가져오기] 하면 된다(전용 크롬 로그인 필요).
- 개발 PC `03_원고\분석_whitedream55_최근글.html` 기준 글(224459320321) 컴포넌트 분석 보고서.
- 개발 PC `원고함\whitedream55\20261102_1351_세종치과_기간\` 테스트 원고(원고.txt + 이미지 8장, 3,004자) → pc-a8 `원고함\whitedream55\` 아래 복사하면 원고·발행 목록에 뜬다. **검사 모드**로만 돌린다.

## 3. 절대 지킬 것
- **whitedream55 는 발행 금지**(사용자 지시). 검사 모드(편집기 입력 + 전수검사, 발행 단계 전 정지)까지만.
- 네이버 아이디·비밀번호는 앱에 저장하지 않고 전용 크롬 창에서 사람이 직접 로그인한다.
- 자동 이웃 신청·댓글·공감 없음. 공식 API만.

## 4. 알려진 문제
- 링크 카드 블록에서 편집기 팝업(`.se-popup-oglink-input`)이 안 열려 44/49 블록에서 2회 실패. editor.js link()는 4회 재시도로 보강됐지만 원인 미확인 → 테스트 때 재현되면 `naver_post/probe_link*.js` 로 툴바 DOM을 떠서 셀렉터 확인.
- 네이버 임시저장에 실패분이 남아 있음(whitedream55: "세종치과 임플란트 기간…" 3건, "오송치과 라미네이트" 1건, "인용구 스타일 시험 (삭제용)" 1건, 제목 없는 probe 1건) → 편집기 저장 목록에서 삭제.
- OpenAI 키 없음(원고·이미지 생성은 Claude가 대신 작성). 검색광고 API 키 미연결(키워드 검색량 꺼짐). 블로그 검색 API(NAVER API HUB)는 PC마다 데이터 설정에 다시 넣어야 함.

## 5. 오늘 추가된 기능 (11-02)
사용자 관리·플랫폼별 권한, 기본 글 형태 템플릿 3개 자동 구성, 히든 이미지(비공개 글 사진 + 아래 문구로 자리 지정), 인용구·구분선 스타일(세로선 등) + 전수검사 대조, 오타·멈춤 사람 습관, 발행 뒤 관련 글 읽기, 이웃 후보, 캐시 비우기, resume.js(중단 지점 이어쓰기), chrome.js(PC별 크롬·puppeteer 자동 탐색).
